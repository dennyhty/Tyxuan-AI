# Tyxuan AI 需求釐清紀錄（grill-me）

- 進行日期：2026-11-10 至 2026-11-12
- 參與者：Denny（鞋廠開發）、Claude
- 目的：釐清「以知識庫為核心、多個 agent 服務各單位」的規劃，作為 road-map 與預算 proposal 的依據
- 客戶名稱一律以代稱表示：第一個導入的客戶為「客戶 A」，第二個為「客戶 B」

## 一、願景

在鞋廠建立一個以知識庫為核心的系統，最終發展出一個或多個具備不同技能的 agent，讓各單位用來解決日常工作。第一個用例是時程規劃：客戶發來 TP 後，agent 依據過往經驗、tracking list、楦頭種類、鞋子功能種類、材料交期、技術與其他風險、當下產線排程與產能、樣品室 loading，產出一份完整的時程規劃。

現階段只做規劃，最終交付 road-map 與預算 proposal。

## 三、樣本檔案分析

### 客戶 A

**Tracking list（SS27）**

- 一個分頁代表一輪樣品：1st Proto（11 列）、2nd Proto（11）、EC sample（25）、EC sample revised（4）、2nd EC sample revised（4）、Drop（8）。
- 節點：TP date、Pullover confirm（最多 4 輪 TB）、Mtrl ETA、Cutting die、Upper jigs、Bottom jigs、Last ETA、Cutting、Second process、Stitching、Assembling、Packing、Sample shipping date。後段分頁另有 PC date、PC released date、Trim BD date。
- 欄位由不同單位填寫：DEV、Material、PE、TE、Planning。
- 每個節點有 Plan 與 Actual 兩欄，但 Actual 多為「/」或空白；狀態常直接寫在 Plan 欄（例如「OK 02/10」「Pending」），沒有年份並混有備註；部分儲存格為公式錯誤。
- 材料到料為一格多行文字，逐家供應商記錄 ETD、ETA、Received。

**TP**

- 5 頁，以手繪圖與照片標註為主，文字少。
- 可讀出的資訊：構造（Strobel、硫化）、面料與內裡、全新開發的鞋墊、楦頭修改 1.5 到 2 mm、單一尺寸可能需開新底模加 logo、配色、客戶來廠日期、EC sample 期限。
- 可被 agent 提前標出的風險實例：TP 要求 EC sample 於 4/2 到，但 tracking list 上新材料的 ETA 為 4/8。

### 客戶 B

**Tracking list（FW26 P1、P2）**

- P1 共 14 列，P2 共 8 列且全數 drop；另有 Last status 分頁。
- 只有材料 ETA、Latest ETA、Pullover 狀態、樣品預計完成日（ETC）、出廠日（X/F）、Sale sample、測試備註。沒有裁斷、針車、成型等製程節點。
- P1 的 TP date 整欄空白；材料欄多半只寫「OK」。

**TP**

- 5 頁，每頁有固定表頭：季節、楦頭、大底模具、樣品尺寸、更新日期。
- 有編號的部位清單、針織結構規格、材料編號與供應商，文字可直接擷取。

### 比較與結論

| | 客戶 A | 客戶 B |
|---|---|---|
| TP 解析難度 | 較高，需圖像判讀 | 較低，格式固定 |
| 歷史紀錄細度 | 有十多個製程節點 | 只有起訖日期 |
| 能支援的產出 | 節點層級的甘特圖 | 只能估整體工期 |

甘特圖需要各製程節點的歷史工期，只有客戶 A 的資料能提供，因此第一個客戶選客戶 A。客戶 B 的 TP 格式適合作為第二個客戶，用來驗證「新增客戶只需新增對照表」。

回測可行，但需要先以 LLM 輔助把自由文字清理成日期。原始計畫日期常被狀態覆蓋，計畫與實際的差距只能部分還原，所以統一 tracking list 格式（Q31）要盡早進行。

## 四、Tech level 代碼

| 代碼 | 意義 |
|---|---|
| TN | Totally New，全新開發 |
| TN+ | Totally New 加新楦頭 |
| NU | New Upper，新鞋面 |
| NU+ | New Upper 加新楦頭 |
| NU- | 鞋面只做小改動 |
| NG | New Graphic，新圖案 |
| NP | New Process，新製程 |
| ND | New cutting Die，新刀模 |
| NM | New Material，新材料 |
| NC | New Color，新配色 |

這組代碼作為時程計算的主要複雜度分級。

## 五、入口方案的查證結果

- **Zalo**：有官方 Bot Platform，建立 bot 取得 token 即可使用；支援群組（需 @ bot）；可用長輪詢，不需對外公開網址；單則訊息上限 2000 字，檔案約 5 MB。
- **個人版 WeChat**：沒有官方 bot API，現有做法多為逆向工程，有封號風險，不採用。
- **企業微信**：有官方 AI 機器人 SDK，支援單聊、群聊與串流回覆，但需公司已有認證的企業微信組織。
